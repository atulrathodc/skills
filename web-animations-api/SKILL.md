# Web Animations API (WAAPI)

`element.animate()` is CSS keyframes as a JS object with a real handle back — you can pause it, seek it, await it, and drive it from scroll. It is the imperative sibling of `css-animation` (see that skill for the CSS side and `motion-design` for what to use).

1. **The one-liner** — `const anim = el.animate([{ opacity: 0 }, { opacity: 1 }], { duration: 300, easing: 'ease-out', fill: 'forwards' })`. The **first argument is the keyframes** (an array of property objects, or a single object with `offset`-keyed frames), the **second is `KeyframeAnimationOptions`**; both are optional-ish (`el.animate(frames)` uses CSS defaults). Swapping them throws a `TypeError` — the #1 WAAPI mistake.
2. **Two keyframe forms** — array form `[{ transform: 'scale(0)' }, { transform: 'scale(1)' }]` auto-distributes offsets; the explicit form `{ transform: ['scale(0)', 'scale(1)'], opacity: [0, 1] }` aligns value arrays across properties. To add a mid stop, use the array of objects with `offset`: `[{opacity:0, offset:0}, {opacity:1, offset:.5}, {opacity:1, offset:1}]`. Numeric properties not given as strings are unitless for most props but `transform`/`opacity` are the safe pair.
3. **Options that matter** — `duration` (ms, required for a visible effect), `delay`, `easing` (`'ease-out'`, `'cubic-bezier(...)'`, `'steps(4, end)'`), `iterations` (`Infinity` to loop), `direction` (`'normal'|'reverse'|'alternate'`), `fill` (`'none'` default → **reverts when it ends**; `'forwards'` keeps the end state; `'both'` also applies the start during the delay), and `composite` (see §8). `fill: 'forwards'` is the WAAPI equivalent of `animation-fill-mode: forwards` — without it your element "snaps back" and it looks like the animation didn't happen.
4. **`Animation` control surface** — `anim.play()`, `pause()`, `reverse()`, `finish()` (jumps to the end), `cancel()` (stops **and removes all effect**, including a `fill: 'forwards'` end state — a common "my element jumped back after cancel" bug; use `commitStyles()` first if you want to keep it), `updatePlaybackRate()`/`anim.playbackRate = 2` (2× speed; negative runs backward, but `reverse()` is clearer), `anim.currentTime` (ms, get **and** set — seeks; set it to replay), and `anim.playState` (`'idle'|'running'|'paused'|'finished'`).
5. **`finished` is a promise you actually await** — `await anim.finished;` resolves when the animation completes, **rejects with an `AbortError` on `cancel()`** (`anim.finished.catch(() => {})` if you don't care) — so wrap scroll/lifecycle code that can cancel. This is the clean way to sequence: `await el.animate(...).finished; await el.animate(...).finished;`.
6. **`fill: 'forwards'` writes an *animated* value that is not the element's style** — `el.style.transform` stays empty, `getComputedStyle` shows the animated value, and a later `el.style.transform = ''` does nothing to it. Persist the end state with `anim.commitStyles()` (writes the computed end value into inline style) and usually `anim.cancel()` after — but only when the element still exists; `commitStyles()` throws if the element was removed from the DOM.
7. **`getAnimations()` finds what is running** — `el.getAnimations()` (or `document.getAnimations()` for all) returns the live `Animation` objects, including CSS-declared ones, so you can pause/seek/cancel a CSS animation from JS and detect duplicates. To avoid stacking animations on re-render, `for (const a of el.getAnimations()) a.cancel();` **before** starting a new one — overlapping `animate()` calls layer (last wins for the same property) and leak memory ("the animation gets faster every click").
8. **Additive animation with `composite`** — the default `composite: 'replace'` overrides the underlying value; `'add'` sums with it (and with other running animations) and `'accumulate'` accumulates iterated values. Use `composite: 'add'` for **layered** motion (a base `translateX` plus a hover nudge) where `'replace'` would wipe the base transform. Mixing the two on the same property is a classic "why did my translate disappear" bug.
9. **`KeyframeEffect` / `Animation` objects directly** — `new KeyframeEffect(target, frames, options)` + `new Animation(effect, document.timeline)` gives you a single reusable effect (retarget with `effect.target = newEl`, repurpose with `anim.effect.updateTiming({duration: 500})`) instead of re-parsing keyframes per element. `document.timeline.currentTime` is the page's shared clock in ms — the right base for syncing multiple animations to one start.
10. **Scroll-driven animation (ScrollTimeline / ViewTimeline)** — `el.animate(frames, { timeline: new ScrollTimeline({ source: scroller, axis: 'block' }), fill: 'both' })` ties progress to scroll offset instead of time; `new ViewTimeline({ subject: el, axis: 'block' })` ties it to the element's position in the viewport (reveal-on-scroll). **With a scroll timeline the `duration` is ignored** (progress is scroll offset), and the timeline must be constructed after the source exists. Chromium-first — feature-detect (`window.ScrollTimeline`) and fall back to an `IntersectionObserver` + normal animation (see `html5-apis`). The CSS-only equivalent is `animation-timeline: scroll()` / `view()`.
11. **Pause on hidden / respect scroll containers** — rAF-adjacent animations keep running when the tab is hidden unless you handle it; page-level animations should pause on `visibilitychange` (see `html5-apis`). For elements inside a scroll container, a `ScrollTimeline` must point at the **scroller** (`source`), not `document`, or progress stays at 0.
12. **Don't mix WAAPI and CSS transitions on the same property** — a running WAAPI animation beats a CSS transition (animations outrank transitions in the cascade), so the transition silently never plays. Pick one per property: `animate()` for scripted/seekable motion, `transition` for state-driven CSS (see `css-animation`).
13. **Clean up on unmount** — cancel animations when a component is removed (`anim.cancel()`), and don't hold `Animation` objects past the element's life (they keep the element alive). In a framework, `useEffect`'s cleanup / `onUnmounted` is the right place; a leaked animation on an HMR-replaced element shows up as "the old one keeps animating".
14. **`prefers-reduced-motion` must be checked in JS** — the CSS media query cannot reach `el.animate()`. Read `matchMedia('(prefers-reduced-motion: reduce)').matches` and either skip the animation, set `duration: 0`, or animate only opacity (see `motion-design`, `accessibility`).
15. **Verify** — in the browser tool, call `el.animate` via a `js` op and assert on the **handle**, not just the visual: `anim.playState === 'running'`, then after the duration `'finished'`, that `await anim.finished` resolves, that `getComputedStyle(el).transform` moved between two sampled times, that `el.getAnimations().length` does **not** grow on repeated triggers (§7), and that a `cancel()` leaves no residual animated value (proves you didn't leak `fill: 'forwards'`). Screenshot mid-flight for the visual cross-check (see `ui-verification`, `browser-agents`).
